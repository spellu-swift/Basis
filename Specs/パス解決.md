# パス解決

FilePathの基準はrelativeTo:で指定し、as:にFilePath.Kindを渡す。
Kindはfileとdirectoryの2種類。as:はKind? = nilを既定値とする。
directoryは基準の全体、fileは基準の親を使用する。
as:を省略、またはnil指定の場合のみ、基準の末尾/があればdirectory、
それ以外はfileとして扱う。明示的なKind指定が末尾/より優先する。
カレントディレクトリとSubprocessの作業ディレクトリは.directoryを明示する。
旧base:引数、FilePath.resolve(path:)、relativeToDirectory:、
relativeToFile:は削除した。

- resolved(relativeTo:as:): パスを結合する。
- absoluted: カレントディレクトリ基準で絶対化する。
- absoluted(relativeTo:as:):
  明示した絶対パスを基準にする。基準の絶対性は事前条件。
- init(relativeTo:as:_:):
  resolvedと同じ解決を行う。
- File、Directoryのabsolutedも同じ基準引数を使う。
- Backbone.resolvePathは上記処理の共通実装。

存在確認や環境変数展開は行わず、未作成パスも扱う。
相対パス内の単独の.は除去するが、..は保持する。
絶対パスの入力は基準に関係なく保持する。
字句的な正規化はnormalized、実体解決はrealpathで明示する。
File・Directoryの生成時も..の自動除去を行わない。

Subprocessは独自のパス連結を行わず、FilePathの絶対化を使う。
プログラム名・PATHの各項目・作業ディレクトリは、変数・~を展開せず文字どおりに解釈し、
子プロセスの作業ディレクトリを基準に絶対化する。PATHは子プロセスに渡す環境変数のものを使う。
URIの相対解決はRFC 3986の独立した処理とし、変更しない。
URI.fileの相対ファイルパス変換はFilePathの絶対化を使う。

## テスト観点

上記APIの各基準種別・両イニシャライザ・File/Directoryラッパーを対象とし、
末尾/の有無、空入力、.、..、ルート、絶対入力、未作成パスを検証する。
カレントディレクトリの検査ではプロセス全体のchdirを使わない。
セマンティックテストは相対シンボリックリンクの解決と、リンク/../の意味を検証する。
Subprocessのプログラム検索の基準と、URIの変換・解決を回帰検証する。

## 移行例

```swift
// ディレクトリ全体を基準にする。
let path: FilePath = FilePath("child")
    .absoluted(relativeTo: "/work/project", as: .directory)
// /work/project/child

// 基準ファイルの親から解決する。
let reference: FilePath = FilePath("child")
    .resolved(relativeTo: "/work/project/document.txt", as: .file)
// /work/project/child
```

基準はStringとFilePathの両方を受け付ける。
既存コードのbase:を機械的に置換せず、基準がファイルかディレクトリか確認する。
